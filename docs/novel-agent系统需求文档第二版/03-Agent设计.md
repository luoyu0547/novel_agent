# Agent 设计

> 第二版需求文档 · 第 3 部分（共 9 部分）  
> [总导航](../novel-agent系统需求文档第二版.md) · [上一页：核心概念](02-核心概念.md) · [下一页：核心产品流程](04-核心产品流程.md)

## 本页内容范围

说明各类 Agent 的职责、输入、输出和不可越权边界。

## 职责总览

| Agent | 核心职责 | 主要产物 | 不可越权边界 |
|---|---|---|---|
| 整体规划 Agent | 管理全书方向和长线结构 | 小说蓝图、卷/篇章规划、章节大纲 | 不直接生成完整章节，不覆盖作者设定或已确认正文 |
| 章节规划 Agent | 把章节大纲细化为写作任务 | 章节任务书、场景列表、验收标准 | 不替代写作 Agent 生成最终正文 |
| 写作 Agent | 按任务书和上下文生成草稿 | 正文草稿、自检、字数统计 | 草稿不直接覆盖正式正文 |
| 检查 Agent | 执行质量门禁并结构化报告问题 | 问题列表、阻断判断、修改建议 | 不负责生成新剧情，早期不直接修改正文 |
| 记忆 Agent | 从已确认正文提取长期信息 | PendingMemory | 未经作者确认不得写入正式记忆 |
| 修改 Agent | 根据问题进行局部、可追踪修复 | 修改草稿、差异和修改理由 | 不默认重写整章，不擅自替换正式版本 |

## Agent 详细设计

### 1. 整体规划 Agent

整体规划 Agent 是第二版最重要的新增 Agent。

它负责从作者输入中生成小说的整体结构，而不是直接写正文。

输入：

| 输入 | 说明 |
|---|---|
| 小说基本信息 | 标题、类型、简介、目标读者、风格指南 |
| 作者意图 | 想写什么故事、喜欢什么爽点或主题 |
| 已有角色 | 已创建的角色卡片 |
| 已有设定 | 已创建的世界观设定 |
| 已有章节 | 如果不是新书，则读取已有章节摘要和事实 |

输出：

| 输出 | 说明 |
|---|---|
| 小说蓝图 | 全书核心承诺、主题、主线冲突、结局方向 |
| 卷/篇章规划 | 每个阶段的起点、终点、冲突、节奏 |
| 主线推进表 | 每条剧情线如何分布到章节或篇章 |
| 角色成长线 | 关键角色每个阶段的变化 |
| 伏笔规划 | 哪些伏笔何时埋设、推进、回收 |
| 章节大纲列表 | 每章的目标、效果和关键事件 |
| 篇幅策略 | 每章大致字数、场景密度和长短章分布 |

边界：

| 不做 | 原因 |
|---|---|
| 不直接生成完整章节正文 | 容易失控，且缺少章节级任务拆解 |
| 不直接覆盖作者已有设定 | 只能生成建议或新版本，需作者确认 |
| 不自动改已确认正文 | 正文变更应由写作/修改链路处理 |

### 2. 章节规划 Agent

章节规划 Agent 负责把整体规划 Agent 给出的章节大纲，拆成写作 Agent 可执行的章节任务书。

输入：

| 输入 | 说明 |
|---|---|
| 当前章节大纲 | 本章在整体规划中的任务 |
| 上下文包 | 与本章相关的角色、设定、事实、伏笔 |
| 上一章状态 | 上一章结尾时的时间、地点、角色状态 |
| 作者补充要求 | 临时想加入的桥段、语气、重点 |

输出：

| 输出 | 说明 |
|---|---|
| 章节任务书 | 写作 Agent 的执行说明 |
| 场景列表 | 本章拆成哪些场景 |
| 角色行动表 | 每个角色在每个场景中的目的和行为 |
| 信息控制表 | 哪些信息可以显性写，哪些只能暗示 |
| 章节效果目标 | 本章要给读者带来的体验 |
| 章节篇幅契约 | 本章目标字数、最低字数、场景字数分配 |
| 验收标准 | 检查 Agent 用来判断成稿是否达标 |

章节规划 Agent 的质量直接决定写作 Agent 输出质量。它应该尽量把“写什么、为什么写、写到什么程度”说清楚。

### 3. 写作 Agent

写作 Agent 是真正生成正文的执行者。

它必须按章节任务书工作，而不是凭空自由发挥。

输入：

| 输入 | 说明 |
|---|---|
| 章节任务书 | 本次写作任务的主约束 |
| 上下文包 | 写作需要遵守的长期信息 |
| 写作模式 | 全章草稿、场景草稿、局部续写、局部改写 |
| 字数和风格约束 | 目标字数、最低字数、视角、语言风格 |

ReAct 执行方式：

```text
1. 阅读章节任务书
2. 调用工具读取相关角色、设定、事实、伏笔
3. 判断本章关键冲突和场景顺序
4. 生成分场景草稿
5. 统计实际字数并检查是否满足篇幅契约
6. 自查是否完成章节效果目标
7. 如果过短，按扩写策略补足有效场景、冲突、反应或细节
8. 必要时局部补写或调整
9. 输出章节草稿、自检说明和字数统计
```

输出：

| 输出 | 说明 |
|---|---|
| 正文草稿 | 可进入编辑器的章节内容 |
| 写作说明 | 本章如何完成任务书 |
| 自检结果 | 写作 Agent 自己发现的潜在问题 |
| 字数统计 | 目标字数、最低字数、实际字数和达标判断 |
| 使用上下文 | 本次写作实际引用了哪些记忆 |

写作 Agent 的输出默认是草稿，不直接覆盖作者正文。作者可以选择接受、编辑、重写或废弃。

### 4. 检查 Agent

检查 Agent 负责质量门禁。

它不负责生成新剧情，早期也不直接自动改正文。

输入：

| 输入 | 说明 |
|---|---|
| 正文草稿 | 写作 Agent 生成或作者编辑后的内容 |
| 章节任务书 | 判断任务完成度 |
| 上下文包 | 判断一致性 |
| 质量标准 | 当前阶段需要检查哪些问题 |

输出格式：

```text
问题类型：
严重程度：阻断 / 重要 / 一般
涉及位置：
问题说明：
关联设定或记忆：
修改建议：
是否阻止确认：是 / 否
```

### 5. 记忆 Agent

记忆 Agent 负责从已确认正文中提取长期信息。

现有 AI 提取能力已经是记忆 Agent 的基础。

第二版中需要明确：只有满足以下条件的内容才应进入正式记忆：

| 条件 | 说明 |
|---|---|
| 来源明确 | 必须来自已确认章节或作者明确输入 |
| 类型明确 | 角色变化、剧情事实、世界设定、伏笔等 |
| 用户确认 | AI 提取结果先进入 PendingMemory |
| 可追溯 | 能追溯到章节、片段或写作运行 |

### 6. 修改 Agent

修改 Agent 后期引入。

它基于检查结果做局部修复，而不是重写整章。

| 功能 | 说明 |
|---|---|
| 局部改写 | 只改有问题的段落 |
| 补充铺垫 | 增加过渡、解释或情绪过程 |
| 删除冲突 | 移除违反设定或提前泄露的信息 |
| 风格统一 | 调整语言节奏和叙述口吻 |
| 版本对比 | 展示改动前后差异 |
