## 本页内容范围

明确第二版当前不建议优先建设的能力，以及后续设计与开发仍需持续细化的问题。

“不建议做”表示当前阶段的优先级和风险判断，不代表永久禁止；“讨论重点”保留原有倾向方向，但仍需要在后续设计与开发中继续细化。

## 当前不建议优先建设的能力

| 功能 | 不建议原因 |
|---|---|
| 一键生成整本小说 | 不可控，质量和一致性难保证 |
| 自动连续生成几十章 | 单章闭环未稳定前会放大错误 |
| 为达标机械灌水 | 会降低阅读质量，篇幅增长必须服务场景和情绪 |
| AI 自动覆盖正式正文 | 容易破坏作者原文 |
| AI 自动写入正式记忆 | 错误记忆会污染后续上下文 |
| 复杂知识图谱优先 | 前期维护成本高，收益不确定 |
| 完整向量 RAG 优先 | 数据结构未稳定前容易返工 |
| 多 Agent 同时并发写作 | 调试困难，问题来源不清 |
| 自动替作者决定所有剧情 | 用户参与感弱，作品容易失控 |

## 后续讨论重点

后续设计和开发应围绕以下问题继续细化：

| 问题 | 倾向方向 |
|---|---|
| 蓝图由作者写还是 AI 生成？ | AI 生成初稿，作者确认激活 |
| 章节计划是否必须存在？ | 是，写作 Agent 应基于任务书执行 |
| 草稿是否直接覆盖章节正文？ | 否，先作为 DraftVersion 或 WritingRun 输出 |
| 检查不过是否禁止接受？ | 阻断问题应强提醒，但作者可强制接受 |
| AI 初稿过短怎么办？ | 不直接通过，按篇幅契约定位缺失场景或情绪过程后扩写 |
| 是否只按总字数判断质量？ | 否，同时检查内容密度，避免机械灌水 |
| 记忆是否自动写入？ | 否，进入 PendingMemory 后确认 |
| 是否一开始做向量检索？ | 否，先做结构化上下文包 |
| 多 Agent 是否并发？ | 否，先按顺序串联，保证可调试 |
