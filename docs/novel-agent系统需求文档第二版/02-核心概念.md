# 核心概念

> 第二版需求文档 · 第 2 部分（共 9 部分）

## 本页内容范围

集中定义第二版自主写作闭环中的核心概念、职责及相互关系。具体字段结构见[数据结构需求](05-数据结构需求.md)。

## 概念总览

| 概念 | 主要作用 | 主要使用者 |
|---|---|---|
| Novel Blueprint | 约束整本书的方向和核心承诺 | 作者、整体规划 Agent |
| Volume Arc | 管理一卷或一个连续阶段的中层结构 | 整体规划 Agent |
| Chapter Outline | 规定单章在全书结构中的任务 | 整体规划 Agent、章节规划 Agent |
| Chapter Brief | 把单章目标细化为可执行写作任务 | 章节规划 Agent、写作 Agent |
| Chapter Effect Target | 规定章节需要带给读者的体验 | 章节规划 Agent、写作 Agent |
| Chapter Length Contract | 约束篇幅、内容密度和扩写方式 | 写作 Agent、检查 Agent |
| Context Package | 提供本次写作所需的压缩上下文 | 写作 Agent |
| Writing Run | 记录一次可追踪的 AI 写作执行 | 作者、写作 Agent、检查 Agent |
| Quality Gate | 判断草稿是否达到确认条件 | 检查 Agent、作者 |
| Plan Version | 追踪规划变化及其影响范围 | 作者、整体规划 Agent |

## 概念详解

### 1. 小说蓝图 Novel Blueprint

小说蓝图是整本书的顶层规划，不是正文，也不是简单简介。

它记录：

| 内容 | 说明 |
|---|---|
| 核心卖点 | 这本书最吸引读者的承诺，例如反转、爽点、关系张力、设定奇观 |
| 主题表达 | 故事最终想讨论或呈现的主题 |
| 主线冲突 | 贯穿全书的核心矛盾 |
| 主要角色弧光 | 主角和关键角色从哪里来，到哪里去 |
| 世界规则 | 影响剧情发展的关键设定 |
| 叙事视角 | 第一人称、第三人称、群像、单主角等 |
| 风格约束 | 文风、节奏、对话密度、禁用表达 |
| 结局方向 | 可以是明确结局，也可以是多个候选方向 |

小说蓝图的作用是限制 AI 不要在后续章节中随意改书的方向。

### 2. 卷/篇章规划 Volume Arc

长篇小说不应该只按单章推进，还需要中层结构。

卷/篇章规划用于记录一个连续阶段的目标：

| 内容 | 说明 |
|---|---|
| 阶段目标 | 这一卷要解决什么问题，制造什么变化 |
| 起点状态 | 本卷开始时世界、角色、关系、冲突的状态 |
| 终点状态 | 本卷结束时必须达成的变化 |
| 关键事件 | 本卷不可缺少的节点 |
| 节奏安排 | 铺垫、升级、爆点、反转、收束的分布 |
| 伏笔安排 | 哪些伏笔要埋设、推进或回收 |

这层规划负责防止每章都只顾眼前热闹，最后主线失焦。

### 3. 章节大纲 Chapter Outline

章节大纲是整体规划 Agent 给章节规划 Agent 的输入。

它回答：**这一章在全书结构中必须完成什么？**

| 内容 | 说明 |
|---|---|
| 本章位置 | 第几章，属于哪一卷或哪一段剧情 |
| 剧情任务 | 本章必须推进的事件 |
| 角色任务 | 本章需要呈现或推动的角色变化 |
| 信息任务 | 本章需要揭露、隐藏或误导的信息 |
| 情绪任务 | 读者读完本章应获得的情绪效果 |
| 节奏任务 | 铺垫、过渡、高潮、反转、收束等 |
| 伏笔任务 | 需要埋设、推进、误导或回收的伏笔 |

### 4. 章节任务书 Chapter Brief

章节任务书是章节规划 Agent 的输出，也是写作 Agent 的主要输入。

它比章节大纲更具体，必须能指导写作 Agent 执行。

章节任务书包括：

| 内容 | 说明 |
|---|---|
| 写作目标 | 本章正文最终应该完成的效果 |
| 场景拆分 | 本章由几个场景组成，每个场景发生什么 |
| 出场角色 | 每个角色在本章的行动、情绪、目的和信息权限 |
| 冲突设计 | 明面冲突、暗线冲突、情绪冲突 |
| 信息控制 | 哪些信息可以说，哪些信息不能说 |
| 伏笔处理 | 哪些细节要写，写到什么程度 |
| 写作约束 | 字数范围、视角、节奏、文风、禁忌 |
| 验收标准 | 写完后如何判断本章达标 |

第二版中，章节任务书是系统最重要的中间产物之一。没有章节任务书，就不应该直接让写作 Agent 生成正文。

### 5. 章节效果目标 Chapter Effect Target

小说章节不是只完成事件，还要完成读者体验。

章节效果目标用于描述读者读完这一章后的感受：

| 类型 | 示例 |
|---|---|
| 爽感 | 主角通过聪明操作扳回一局 |
| 压迫感 | 反派首次展现不可战胜的优势 |
| 悬念 | 结尾抛出一个让读者想翻下一章的问题 |
| 情绪释放 | 两个角色完成一次迟来的和解 |
| 信息震动 | 读者意识到之前的线索另有含义 |
| 期待感 | 新目标、新地图、新敌人出现 |

章节规划 Agent 必须明确本章效果目标，写作 Agent 必须围绕这个目标组织正文。

### 6. 章节篇幅契约 Chapter Length Contract

章节篇幅契约用于防止 AI 为了“完成任务”而把章节写得过短。

小说章节不能只看是否交代完事件，还要看是否给足过程、冲突、反应、铺垫和阅读节奏。对于长篇小说，章节长度本身也是结构的一部分：如果每章都用很短内容快速完成目标，整本书会变成剧情梗概，而不是可阅读的小说。

章节篇幅契约记录：

| 内容 | 说明 |
|---|---|
| 目标字数 | 本章理想输出字数，例如 3000 字、5000 字 |
| 最低字数 | 低于该字数默认不能通过质量门禁 |
| 最高字数 | 防止单章过长导致节奏失衡 |
| 场景字数分配 | 每个场景大致承担多少篇幅 |
| 内容密度要求 | 字数增长必须来自有效场景、动作、心理、对话和细节，而不是空泛重复 |
| 扩写策略 | 如果初稿过短，优先扩写哪些场景、冲突、反应或铺垫 |
| 压缩策略 | 如果初稿过长，优先压缩哪些说明、重复和低价值描写 |

篇幅契约不是为了灌水，而是为了确保章节有足够的小说质感。写作 Agent 如果未达到最低字数，应该先判断缺失的是场景过程、情绪反应、冲突升级、环境动作还是对话推进，再进行有意义的扩写。

### 7. 上下文包 Context Package

上下文包是写作 Agent 每次执行前拿到的压缩输入。

它不是把全书全文塞进模型，而是由系统整理出与本章相关的信息：

```text
当前章节上下文包：
1. 小说蓝图摘要
2. 当前卷/篇章目标
3. 本章章节任务书
4. 上一章摘要与结尾状态
5. 相关角色卡片与当前状态
6. 相关世界观设定
7. 相关剧情事实
8. 未回收或本章相关伏笔
9. 信息权限与禁止提前揭露内容
10. 写作风格指南
11. 章节篇幅契约与场景字数分配
12. 质量验收标准
```

上下文包设计是系统能否稳定写长篇的关键。

### 8. 写作运行 Writing Run

写作运行是一次 AI 自主写作任务的记录。

它记录：

| 内容 | 说明 |
|---|---|
| 输入 | 使用了哪个章节任务书和上下文包 |
| 模式 | 标准生成、深度生成、局部续写、改写等 |
| ReAct 步骤 | Agent 读取了什么、判断了什么、执行了什么 |
| 输出 | 生成的章节草稿或片段 |
| 字数统计 | 目标字数、实际字数、是否达标 |
| 检查结果 | 是否通过质量门禁 |
| 作者处理 | 接受、要求重写、局部修改、废弃 |

写作运行让 AI 写作过程可追踪，而不是一次黑箱调用。

### 9. 质量门禁 Quality Gate

质量门禁是正文进入“可确认草稿”前必须经过的检查。

质量门禁初期不要求自动修复，但必须能输出问题。

| 检查项 | 说明 |
|---|---|
| 任务完成度 | 是否完成章节任务书中的剧情、角色、情绪目标 |
| 人设一致性 | 角色行为、说话方式、信息权限是否合理 |
| 剧情连续性 | 时间、地点、物品、关系、知识是否冲突 |
| 伏笔控制 | 是否遗漏、提前揭露、重复解释或误导过度 |
| 篇幅达标 | 是否达到章节篇幅契约的最低字数和目标字数范围 |
| 内容密度 | 扩写内容是否有效推进场景、人物、情绪或信息，而不是重复灌水 |
| 世界观一致性 | 是否违反已确认设定 |
| 风格一致性 | 是否偏离小说风格指南 |
| 可读性 | 是否有明显空泛、重复、节奏拖沓或逻辑跳跃 |

质量门禁的输出是问题列表，不默认自动修改正文。

### 10. 计划版本 Plan Version

小说规划会变，不能假设第一次生成的大纲永远正确。

计划版本用于保存规划变化：

| 内容 | 说明 |
|---|---|
| 版本号 | 第几版蓝图或章节计划 |
| 变更原因 | 作者修改、检查发现问题、剧情自然演化 |
| 影响范围 | 影响哪些卷、章节、角色、伏笔 |
| 是否生效 | 草稿计划、当前计划、废弃计划 |

计划版本可以避免 AI 后续写作引用已经废弃的旧大纲。
