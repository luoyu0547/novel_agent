## 写作工作台与页面

第二版的产品入口应该从“资料管理页面集合”升级为“写作工作台”。

### MVP 页面

| 页面 | 功能 |
|---|---|
| 小说工作台 | 展示当前蓝图、当前章节计划、下一步动作 |
| 蓝图页 | 生成、编辑、确认小说蓝图 |
| 规划页 | 查看卷/篇章规划和章节大纲列表 |
| 章节任务书页 | 生成和编辑本章任务书、篇幅契约和场景字数分配 |
| AI 写作页 | 运行写作 Agent，查看草稿、自检、字数统计和使用上下文 |
| 章节编辑页 | 作者编辑最终正文 |
| 检查页 | 查看 ReviewIssue 和修改建议 |
| 待确认记忆页 | 确认或拒绝 AI 提取的长期记忆 |
| 角色/设定/伏笔页 | 管理支撑资料 |

### 工作台优先展示的信息

```text
当前小说：
当前蓝图版本：
当前卷目标：
下一章计划：
下一章目标字数：
下一步建议动作：生成任务书 / 生成草稿 / 检查草稿 / 确认记忆
未解决问题：
待确认记忆：
```

## 关键设计原则

### 1. AI 可以自主执行，但不能绕过作者确认

AI 可以生成蓝图、计划、正文草稿、检查结果和记忆候选，但以下内容必须由作者确认：

| 内容 | 原因 |
|---|---|
| 激活的小说蓝图 | 决定整本书方向 |
| 正式章节正文 | 直接影响作品内容 |
| 正式长期记忆 | 错误记忆会污染后续生成 |
| 重大伏笔状态变化 | 提前或错误回收会破坏长线结构 |

### 2. 先生成计划，再生成正文

写作 Agent 不应该直接根据一句“写下一章”生成正文。

正确路径是：

```text
章节大纲 → 章节任务书 → 上下文包 → 正文草稿
```

这样系统才能追踪 AI 为什么这样写，也才能检查正文是否完成任务。

### 3. 记忆必须可追溯、可确认、可撤销

长期记忆是后续生成的基础，因此不能让模型随意写入。

所有 AI 提取结果应进入 PendingMemory，并尽量记录来源章节、来源片段、提取原因和影响范围。

### 4. 检查优先于自动修复

早期重点是让系统发现问题，而不是自动改掉问题。

如果检查结果不可靠，自动修复只会扩大错误。

### 5. 长篇结构优先于单次生成效果

单章写得热闹不代表长篇好看。

系统需要持续维护：主线推进、角色成长、伏笔生命周期、读者期待和信息揭露节奏。

### 6. 篇幅控制是质量约束，不是灌水要求

章节目标不能只写“完成某个剧情任务”，还要写清楚该任务需要多少篇幅来呈现。

如果 AI 用很短内容说完任务，系统应判断为“章节展开不足”，而不是默认完成。补足字数时必须增加有效内容，例如场景过程、角色反应、冲突升级、对话推进、动作细节、氛围铺垫和信息误导，不能靠重复说明、空泛心理描写或无关闲聊凑字数。
