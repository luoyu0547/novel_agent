# novel-agent 系统需求文档第二版

## 一、第二版核心定位

第一版文档把系统重点放在“章节编辑 + 长期记忆 + 一致性检查”上，这些能力对长篇小说很重要，但它们更像是小说创作系统的支撑层。对于小说来说，最核心的 AI 能力应该是：**AI 能在作者给定的方向内，自主完成从全书规划到章节草稿的写作闭环。**

第二版将系统定位调整为：**作者可控的 AI 自主写作工作台**。

它不是“一键生成整本小说”，也不是单纯的文本编辑器，而是让作者可以像管理一个创作团队一样管理 AI：

| 层级 | 说明 |
|---|---|
| 作者 | 提供创作意图、审核方向、批准关键记忆和正文版本 |
| 整体规划 Agent | 负责小说蓝图、主线结构、卷/篇章大纲和长期节奏 |
| 章节规划 Agent | 负责把本章大纲拆成可执行的章节任务书 |
| 写作 Agent | 负责按章节任务书和上下文包，用 ReAct 方式生成正文草稿 |
| 检查 Agent | 负责发现人设、设定、伏笔、连续性和风格问题 |
| 记忆 Agent | 负责从已确认正文中提取结构化记忆，进入待确认区 |

第二版的主线是：**规划驱动写作，写作产生正文，正文反哺记忆，记忆再支撑后续规划和写作。**

------

## 二、当前项目基线

根据现有项目实现，系统已经具备以下基础能力：

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 用户认证 | 已实现 | 注册、登录、JWT 鉴权 |
| 小说项目 | 已实现 | `Novel` 支持标题、简介、类型、写作风格指南 |
| 章节管理 | 已实现 | `Chapter` 支持标题、正文、摘要、状态 |
| 章节编辑 | 已实现基础版 | 前端有章节编辑页和保存能力 |
| 角色卡片 | 已实现 | `CharacterProfile` 支持身份、性格、动机、说话方式、行为规则、当前状态 |
| 世界观设定 | 已实现 | `WorldSetting` 支持分类设定维护 |
| 剧情事实 | 已有模型 | `PlotFact` 支持事件、关系、地点、物品、知识等事实 |
| 伏笔管理 | 已有模型 | `Foreshadowing` 支持埋设、推进、回收状态和风险提示 |
| 待确认记忆 | 已实现 | `PendingMemory` 支持 AI 提取结果确认或拒绝 |
| AI 提取骨架 | 已实现基础版 | 已有 LangChain / ReAct Agent、上下文读取工具和记忆写入工具 |

这说明项目已经完成了“长期创作资料的底座”，但还没有完成第二版最核心的能力：**AI 自主生成可用章节草稿的规划与执行闭环。**

当前缺口不是“再加几个记忆页面”，而是需要建立一个清晰的写作链路：

```text
小说蓝图
↓
卷/篇章大纲
↓
章节大纲
↓
章节任务书
↓
上下文包
↓
写作 Agent ReAct 生成正文
↓
检查问题
↓
作者确认正文
↓
记忆提取与待确认
↓
更新长期创作状态
```

## 三、第二版新增核心概念

### 1. 小说蓝图 Novel Blueprint

小说蓝图是整本书的顶层规划，不是正文，也不是简单简介。

它记录：

| 内容 | 说明 |
|---|---|
| 核心卖点 | 这本书最吸引读者的承诺，例如反转、爽点、关系张力、设定奇观 |
| 主题表达 | 故事最终想讨论或呈现的主题 |
| 主线冲突 | 贯穿全书的核心矛盾 |
| 主要角色弧光 | 主角和关键角色从哪里来，到哪里去 |
| 世界规则 | 影响剧情发展的关键设定 |
| 叙事视角 | 第一人称、第三人称、群像、单主角等 |
| 风格约束 | 文风、节奏、对话密度、禁用表达 |
| 结局方向 | 可以是明确结局，也可以是多个候选方向 |

小说蓝图的作用是限制 AI 不要在后续章节中随意改书的方向。

### 2. 卷/篇章规划 Volume Arc

长篇小说不应该只按单章推进，还需要中层结构。

卷/篇章规划用于记录一个连续阶段的目标：

| 内容 | 说明 |
|---|---|
| 阶段目标 | 这一卷要解决什么问题，制造什么变化 |
| 起点状态 | 本卷开始时世界、角色、关系、冲突的状态 |
| 终点状态 | 本卷结束时必须达成的变化 |
| 关键事件 | 本卷不可缺少的节点 |
| 节奏安排 | 铺垫、升级、爆点、反转、收束的分布 |
| 伏笔安排 | 哪些伏笔要埋设、推进或回收 |

这层规划负责防止每章都只顾眼前热闹，最后主线失焦。

### 3. 章节大纲 Chapter Outline

章节大纲是整体规划 Agent 给章节规划 Agent 的输入。

它回答：**这一章在全书结构中必须完成什么？**

| 内容 | 说明 |
|---|---|
| 本章位置 | 第几章，属于哪一卷或哪一段剧情 |
| 剧情任务 | 本章必须推进的事件 |
| 角色任务 | 本章需要呈现或推动的角色变化 |
| 信息任务 | 本章需要揭露、隐藏或误导的信息 |
| 情绪任务 | 读者读完本章应获得的情绪效果 |
| 节奏任务 | 铺垫、过渡、高潮、反转、收束等 |
| 伏笔任务 | 需要埋设、推进、误导或回收的伏笔 |

### 4. 章节任务书 Chapter Brief

章节任务书是章节规划 Agent 的输出，也是写作 Agent 的主要输入。

它比章节大纲更具体，必须能指导写作 Agent 执行。

章节任务书包括：

| 内容 | 说明 |
|---|---|
| 写作目标 | 本章正文最终应该完成的效果 |
| 场景拆分 | 本章由几个场景组成，每个场景发生什么 |
| 出场角色 | 每个角色在本章的行动、情绪、目的和信息权限 |
| 冲突设计 | 明面冲突、暗线冲突、情绪冲突 |
| 信息控制 | 哪些信息可以说，哪些信息不能说 |
| 伏笔处理 | 哪些细节要写，写到什么程度 |
| 写作约束 | 字数范围、视角、节奏、文风、禁忌 |
| 验收标准 | 写完后如何判断本章达标 |

第二版中，章节任务书是系统最重要的中间产物之一。没有章节任务书，就不应该直接让写作 Agent 生成正文。

### 5. 章节效果目标 Chapter Effect Target

小说章节不是只完成事件，还要完成读者体验。

章节效果目标用于描述读者读完这一章后的感受：

| 类型 | 示例 |
|---|---|
| 爽感 | 主角通过聪明操作扳回一局 |
| 压迫感 | 反派首次展现不可战胜的优势 |
| 悬念 | 结尾抛出一个让读者想翻下一章的问题 |
| 情绪释放 | 两个角色完成一次迟来的和解 |
| 信息震动 | 读者意识到之前的线索另有含义 |
| 期待感 | 新目标、新地图、新敌人出现 |

章节规划 Agent 必须明确本章效果目标，写作 Agent 必须围绕这个目标组织正文。

### 6. 章节篇幅契约 Chapter Length Contract

章节篇幅契约用于防止 AI 为了“完成任务”而把章节写得过短。

小说章节不能只看是否交代完事件，还要看是否给足过程、冲突、反应、铺垫和阅读节奏。对于长篇小说，章节长度本身也是结构的一部分：如果每章都用很短内容快速完成目标，整本书会变成剧情梗概，而不是可阅读的小说。

章节篇幅契约记录：

| 内容 | 说明 |
|---|---|
| 目标字数 | 本章理想输出字数，例如 3000 字、5000 字 |
| 最低字数 | 低于该字数默认不能通过质量门禁 |
| 最高字数 | 防止单章过长导致节奏失衡 |
| 场景字数分配 | 每个场景大致承担多少篇幅 |
| 内容密度要求 | 字数增长必须来自有效场景、动作、心理、对话和细节，而不是空泛重复 |
| 扩写策略 | 如果初稿过短，优先扩写哪些场景、冲突、反应或铺垫 |
| 压缩策略 | 如果初稿过长，优先压缩哪些说明、重复和低价值描写 |

篇幅契约不是为了灌水，而是为了确保章节有足够的小说质感。写作 Agent 如果未达到最低字数，应该先判断缺失的是场景过程、情绪反应、冲突升级、环境动作还是对话推进，再进行有意义的扩写。

### 7. 上下文包 Context Package

上下文包是写作 Agent 每次执行前拿到的压缩输入。

它不是把全书全文塞进模型，而是由系统整理出与本章相关的信息：

```text
当前章节上下文包：
1. 小说蓝图摘要
2. 当前卷/篇章目标
3. 本章章节任务书
4. 上一章摘要与结尾状态
5. 相关角色卡片与当前状态
6. 相关世界观设定
7. 相关剧情事实
8. 未回收或本章相关伏笔
9. 信息权限与禁止提前揭露内容
10. 写作风格指南
11. 章节篇幅契约与场景字数分配
12. 质量验收标准
```

上下文包设计是系统能否稳定写长篇的关键。

### 8. 写作运行 Writing Run

写作运行是一次 AI 自主写作任务的记录。

它记录：

| 内容 | 说明 |
|---|---|
| 输入 | 使用了哪个章节任务书和上下文包 |
| 模式 | 标准生成、深度生成、局部续写、改写等 |
| ReAct 步骤 | Agent 读取了什么、判断了什么、执行了什么 |
| 输出 | 生成的章节草稿或片段 |
| 字数统计 | 目标字数、实际字数、是否达标 |
| 检查结果 | 是否通过质量门禁 |
| 作者处理 | 接受、要求重写、局部修改、废弃 |

写作运行让 AI 写作过程可追踪，而不是一次黑箱调用。

### 9. 质量门禁 Quality Gate

质量门禁是正文进入“可确认草稿”前必须经过的检查。

质量门禁初期不要求自动修复，但必须能输出问题。

| 检查项 | 说明 |
|---|---|
| 任务完成度 | 是否完成章节任务书中的剧情、角色、情绪目标 |
| 人设一致性 | 角色行为、说话方式、信息权限是否合理 |
| 剧情连续性 | 时间、地点、物品、关系、知识是否冲突 |
| 伏笔控制 | 是否遗漏、提前揭露、重复解释或误导过度 |
| 篇幅达标 | 是否达到章节篇幅契约的最低字数和目标字数范围 |
| 内容密度 | 扩写内容是否有效推进场景、人物、情绪或信息，而不是重复灌水 |
| 世界观一致性 | 是否违反已确认设定 |
| 风格一致性 | 是否偏离小说风格指南 |
| 可读性 | 是否有明显空泛、重复、节奏拖沓或逻辑跳跃 |

质量门禁的输出是问题列表，不默认自动修改正文。

### 10. 计划版本 Plan Version

小说规划会变，不能假设第一次生成的大纲永远正确。

计划版本用于保存规划变化：

| 内容 | 说明 |
|---|---|
| 版本号 | 第几版蓝图或章节计划 |
| 变更原因 | 作者修改、检查发现问题、剧情自然演化 |
| 影响范围 | 影响哪些卷、章节、角色、伏笔 |
| 是否生效 | 草稿计划、当前计划、废弃计划 |

计划版本可以避免 AI 后续写作引用已经废弃的旧大纲。

## 四、核心 Agent 设计

### 1. 整体规划 Agent

整体规划 Agent 是第二版最重要的新增 Agent。

它负责从作者输入中生成小说的整体结构，而不是直接写正文。

输入：

| 输入 | 说明 |
|---|---|
| 小说基本信息 | 标题、类型、简介、目标读者、风格指南 |
| 作者意图 | 想写什么故事、喜欢什么爽点或主题 |
| 已有角色 | 已创建的角色卡片 |
| 已有设定 | 已创建的世界观设定 |
| 已有章节 | 如果不是新书，则读取已有章节摘要和事实 |

输出：

| 输出 | 说明 |
|---|---|
| 小说蓝图 | 全书核心承诺、主题、主线冲突、结局方向 |
| 卷/篇章规划 | 每个阶段的起点、终点、冲突、节奏 |
| 主线推进表 | 每条剧情线如何分布到章节或篇章 |
| 角色成长线 | 关键角色每个阶段的变化 |
| 伏笔规划 | 哪些伏笔何时埋设、推进、回收 |
| 章节大纲列表 | 每章的目标、效果和关键事件 |
| 篇幅策略 | 每章大致字数、场景密度和长短章分布 |

边界：

| 不做 | 原因 |
|---|---|
| 不直接生成完整章节正文 | 容易失控，且缺少章节级任务拆解 |
| 不直接覆盖作者已有设定 | 只能生成建议或新版本，需作者确认 |
| 不自动改已确认正文 | 正文变更应由写作/修改链路处理 |

### 2. 章节规划 Agent

章节规划 Agent 负责把整体规划 Agent 给出的章节大纲，拆成写作 Agent 可执行的章节任务书。

输入：

| 输入 | 说明 |
|---|---|
| 当前章节大纲 | 本章在整体规划中的任务 |
| 上下文包 | 与本章相关的角色、设定、事实、伏笔 |
| 上一章状态 | 上一章结尾时的时间、地点、角色状态 |
| 作者补充要求 | 临时想加入的桥段、语气、重点 |

输出：

| 输出 | 说明 |
|---|---|
| 章节任务书 | 写作 Agent 的执行说明 |
| 场景列表 | 本章拆成哪些场景 |
| 角色行动表 | 每个角色在每个场景中的目的和行为 |
| 信息控制表 | 哪些信息可以显性写，哪些只能暗示 |
| 章节效果目标 | 本章要给读者带来的体验 |
| 章节篇幅契约 | 本章目标字数、最低字数、场景字数分配 |
| 验收标准 | 检查 Agent 用来判断成稿是否达标 |

章节规划 Agent 的质量直接决定写作 Agent 输出质量。它应该尽量把“写什么、为什么写、写到什么程度”说清楚。

### 3. 写作 Agent

写作 Agent 是真正生成正文的执行者。

它必须按章节任务书工作，而不是凭空自由发挥。

输入：

| 输入 | 说明 |
|---|---|
| 章节任务书 | 本次写作任务的主约束 |
| 上下文包 | 写作需要遵守的长期信息 |
| 写作模式 | 全章草稿、场景草稿、局部续写、局部改写 |
| 字数和风格约束 | 目标字数、最低字数、视角、语言风格 |

ReAct 执行方式：

```text
1. 阅读章节任务书
2. 调用工具读取相关角色、设定、事实、伏笔
3. 判断本章关键冲突和场景顺序
4. 生成分场景草稿
5. 统计实际字数并检查是否满足篇幅契约
6. 自查是否完成章节效果目标
7. 如果过短，按扩写策略补足有效场景、冲突、反应或细节
8. 必要时局部补写或调整
9. 输出章节草稿、自检说明和字数统计
```

输出：

| 输出 | 说明 |
|---|---|
| 正文草稿 | 可进入编辑器的章节内容 |
| 写作说明 | 本章如何完成任务书 |
| 自检结果 | 写作 Agent 自己发现的潜在问题 |
| 字数统计 | 目标字数、最低字数、实际字数和达标判断 |
| 使用上下文 | 本次写作实际引用了哪些记忆 |

写作 Agent 的输出默认是草稿，不直接覆盖作者正文。作者可以选择接受、编辑、重写或废弃。

### 4. 检查 Agent

检查 Agent 负责质量门禁。

它不负责生成新剧情，早期也不直接自动改正文。

输入：

| 输入 | 说明 |
|---|---|
| 正文草稿 | 写作 Agent 生成或作者编辑后的内容 |
| 章节任务书 | 判断任务完成度 |
| 上下文包 | 判断一致性 |
| 质量标准 | 当前阶段需要检查哪些问题 |

输出格式：

```text
问题类型：
严重程度：阻断 / 重要 / 一般
涉及位置：
问题说明：
关联设定或记忆：
修改建议：
是否阻止确认：是 / 否
```

### 5. 记忆 Agent

记忆 Agent 负责从已确认正文中提取长期信息。

现有 AI 提取能力已经是记忆 Agent 的基础。

第二版中需要明确：只有满足以下条件的内容才应进入正式记忆：

| 条件 | 说明 |
|---|---|
| 来源明确 | 必须来自已确认章节或作者明确输入 |
| 类型明确 | 角色变化、剧情事实、世界设定、伏笔等 |
| 用户确认 | AI 提取结果先进入 PendingMemory |
| 可追溯 | 能追溯到章节、片段或写作运行 |

### 6. 修改 Agent

修改 Agent 后期引入。

它基于检查结果做局部修复，而不是重写整章。

| 功能 | 说明 |
|---|---|
| 局部改写 | 只改有问题的段落 |
| 补充铺垫 | 增加过渡、解释或情绪过程 |
| 删除冲突 | 移除违反设定或提前泄露的信息 |
| 风格统一 | 调整语言节奏和叙述口吻 |
| 版本对比 | 展示改动前后差异 |

## 五、第二版核心产品流程

### 1. 新书启动流程

```text
创建小说项目
↓
填写类型、简介、风格指南和作者意图
↓
创建或导入基础角色、世界观设定
↓
整体规划 Agent 生成小说蓝图
↓
作者审核并确认蓝图
↓
整体规划 Agent 生成卷/篇章规划和章节大纲列表
↓
作者选择要开始写的章节
↓
章节规划 Agent 生成章节任务书
↓
写作 Agent 生成正文草稿
↓
检查 Agent 输出问题
↓
作者确认、编辑或要求重写
↓
确认后的正文触发记忆 Agent 提取
↓
作者确认 PendingMemory
↓

```

### 2. 已有小说续写流程

```text
导入或维护已有章节
↓
为已有章节生成摘要和剧情事实
↓
提取角色状态、世界设定和伏笔候选
↓
作者确认记忆
↓
整体规划 Agent 基于已有内容补全后续规划
↓
章节规划 Agent 生成下一章任务书
↓
写作 Agent 续写
```

### 3. 单章自主写作流程

```text
选择章节大纲
↓
生成章节任务书
↓
生成上下文包
↓
写作 Agent ReAct 执行
↓
输出章节草稿
↓
检查 Agent 评估
↓
作者处理草稿
```

### 4. 章节确认后的记忆回写流程

```text
章节正文被作者确认
↓
记忆 Agent 提取结构化信息
↓
生成 PendingMemory
↓
作者逐条确认或拒绝
↓
正式写入角色、设定、剧情事实、伏笔
↓
后续规划和写作可检索使用
```

## 七、阶段路线图

### 阶段 0：已有基础能力

状态：基本已具备。

| 能力 | 说明 |
|---|---|
| 小说项目管理 | 创建、查看、编辑、删除小说 |
| 章节管理 | 创建、编辑、保存章节 |
| 人工记忆管理 | 角色、世界观设定 |
| 基础 AI 提取 | 从章节提取结构化记忆候选 |
| 待确认区 | AI 提取结果必须用户确认 |

阶段 0 的价值是提供长期写作资料底座。

### 阶段 1：最小自主写作闭环

目标：实现从规划到章节草稿的最短路径。

优先实现：

| 功能 | 说明 |
|---|---|
| 小说蓝图生成 | 根据小说信息和作者意图生成第一版蓝图 |
| 章节大纲生成 | 生成若干章的章节目标和效果目标 |
| 章节任务书生成 | 把章节大纲拆成可执行任务 |
| 章节篇幅契约生成 | 明确目标字数、最低字数、最高字数和场景字数分配 |
| 上下文包生成 | 汇总本章需要的角色、设定、事实、伏笔 |
| 写作 Agent 生成草稿 | 根据任务书生成正文草稿 |
| 字数达标检查 | 草稿过短时要求按扩写策略补足有效内容 |
| 草稿进入编辑器 | 作者可以接受、修改或废弃 |

暂不实现：

| 暂不做 | 原因 |
|---|---|
| 自动连续生成多章 | 先保证单章质量 |
| 自动改正式记忆 | 防止错误污染 |
| 自动修复所有检查问题 | 先输出问题，后做修改 Agent |
| 复杂向量检索 | 先用结构化上下文包跑通闭环 |

阶段 1 成功标准：作者能从一个小说构思生成章节任务书，并让 AI 按目标字数写出一章可编辑草稿，而不是只生成剧情梗概式短章。

### 阶段 2：章节质量门禁

目标：让生成草稿可检查、可判断、可迭代。

新增功能：

| 功能 | 说明 |
|---|---|
| 任务完成度检查 | 是否完成章节任务书 |
| 人设一致性检查 | 角色行为和说话方式是否合理 |
| 剧情连续性检查 | 时间、地点、关系、物品、信息是否冲突 |
| 伏笔检查 | 是否提前揭露、遗漏或重复解释 |
| 篇幅检查 | 是否达到章节篇幅契约，是否存在为凑字数产生的低价值重复 |
| 风格检查 | 是否符合风格指南 |
| ReviewIssue 列表 | 固定格式记录问题 |

阶段 2 成功标准：每次 AI 草稿都能附带清晰的问题列表和是否建议接受的判断。

### 阶段 3：规划版本与长篇结构管理

目标：让系统能支撑中长篇，而不是只写下一章。

新增功能：

| 功能 | 说明 |
|---|---|
| 计划版本管理 | 蓝图、卷规划、章节计划支持版本 |
| 卷/篇章规划 | 支持中层结构管理 |
| 主线推进表 | 记录每条剧情线在各章推进情况 |
| 角色成长线 | 记录关键角色阶段性变化 |
| 伏笔生命周期 | 规划和追踪埋设、推进、误导、回收 |

阶段 3 成功标准：AI 能解释当前章节为什么这样写，以及它如何服务于后续长线规划。

### 阶段 4：辅助修改与版本管理

目标：让 AI 不只会写第一稿，还能基于问题做可控修改。

新增功能：

| 功能 | 说明 |
|---|---|
| 局部改写 | 根据 ReviewIssue 修改指定片段 |
| 修改方案生成 | 给出多个修复方向 |
| DraftVersion | 保存章节草稿版本 |
| 差异对比 | 展示修改前后差异 |
| 修改理由记录 | 说明为什么这样改 |

阶段 4 成功标准：作者可以围绕一章进行“生成 → 检查 → 局部修改 → 接受”的闭环。

### 阶段 5：高级上下文与检索

目标：提升长篇后期的上下文准确性。

新增功能：

| 功能 | 说明 |
|---|---|
| 相关章节检索 | 根据当前任务找到历史相关章节 |
| 角色历史检索 | 找角色过去行为和关系变化 |
| 伏笔风险检索 | 找出当前章节不能提前暴露的信息 |
| 设定冲突检索 | 找出可能冲突的世界规则 |
| 向量检索可选接入 | 数据结构稳定后再引入 |

阶段 5 成功标准：写到长篇后期时，系统仍能找到正确上下文，减少遗忘和矛盾。

## 九、关键设计原则

### 1. AI 可以自主执行，但不能绕过作者确认

AI 可以生成蓝图、计划、正文草稿、检查结果和记忆候选，但以下内容必须由作者确认：

| 内容 | 原因 |
|---|---|
| 激活的小说蓝图 | 决定整本书方向 |
| 正式章节正文 | 直接影响作品内容 |
| 正式长期记忆 | 错误记忆会污染后续生成 |
| 重大伏笔状态变化 | 提前或错误回收会破坏长线结构 |

### 2. 先生成计划，再生成正文

写作 Agent 不应该直接根据一句“写下一章”生成正文。

正确路径是：

```text
章节大纲 → 章节任务书 → 上下文包 → 正文草稿
```

这样系统才能追踪 AI 为什么这样写，也才能检查正文是否完成任务。

### 3. 记忆必须可追溯、可确认、可撤销

长期记忆是后续生成的基础，因此不能让模型随意写入。

所有 AI 提取结果应进入 PendingMemory，并尽量记录来源章节、来源片段、提取原因和影响范围。

### 4. 检查优先于自动修复

早期重点是让系统发现问题，而不是自动改掉问题。

如果检查结果不可靠，自动修复只会扩大错误。

### 5. 长篇结构优先于单次生成效果

单章写得热闹不代表长篇好看。

系统需要持续维护：主线推进、角色成长、伏笔生命周期、读者期待和信息揭露节奏。

### 6. 篇幅控制是质量约束，不是灌水要求

章节目标不能只写“完成某个剧情任务”，还要写清楚该任务需要多少篇幅来呈现。

如果 AI 用很短内容说完任务，系统应判断为“章节展开不足”，而不是默认完成。补足字数时必须增加有效内容，例如场景过程、角色反应、冲突升级、对话推进、动作细节、氛围铺垫和信息误导，不能靠重复说明、空泛心理描写或无关闲聊凑字数。

## 十、第二版不建议做的功能

| 功能 | 不建议原因 |
|---|---|
| 一键生成整本小说 | 不可控，质量和一致性难保证 |
| 自动连续生成几十章 | 单章闭环未稳定前会放大错误 |
| 为达标机械灌水 | 会降低阅读质量，篇幅增长必须服务场景和情绪 |
| AI 自动覆盖正式正文 | 容易破坏作者原文 |
| AI 自动写入正式记忆 | 错误记忆会污染后续上下文 |
| 复杂知识图谱优先 | 前期维护成本高，收益不确定 |
| 完整向量 RAG 优先 | 数据结构未稳定前容易返工 |
| 多 Agent 同时并发写作 | 调试困难，问题来源不清 |
| 自动替作者决定所有剧情 | 用户参与感弱，作品容易失控 |

## 十一、第二版讨论重点

后续设计和开发应围绕以下问题继续细化：

| 问题 | 倾向方向 |
|---|---|
| 蓝图由作者写还是 AI 生成？ | AI 生成初稿，作者确认激活 |
| 章节计划是否必须存在？ | 是，写作 Agent 应基于任务书执行 |
| 草稿是否直接覆盖章节正文？ | 否，先作为 DraftVersion 或 WritingRun 输出 |
| 检查不过是否禁止接受？ | 阻断问题应强提醒，但作者可强制接受 |
| AI 初稿过短怎么办？ | 不直接通过，按篇幅契约定位缺失场景或情绪过程后扩写 |
| 是否只按总字数判断质量？ | 否，同时检查内容密度，避免机械灌水 |
| 记忆是否自动写入？ | 否，进入 PendingMemory 后确认 |
| 是否一开始做向量检索？ | 否，先做结构化上下文包 |
| 多 Agent 是否并发？ | 否，先按顺序串联，保证可调试 |

## 十二、第二版最小可验证目标

第二版最小目标不是“让系统一次写完一本书”，而是验证以下闭环：

```text
作者输入小说构思
↓
AI 生成小说蓝图
↓
作者确认蓝图
↓
AI 生成某一章章节任务书
↓
AI 根据任务书和上下文包生成章节草稿
↓
AI 统计字数并按篇幅契约补足有效内容
↓
AI 检查草稿是否达成章节目标
↓
作者接受或修改草稿
↓
AI 提取记忆候选
↓
作者确认记忆
↓
下一章能使用这些记忆继续规划和写作
```

只要这个闭环跑通，后续的伏笔管理、角色一致性、版本管理、向量检索和复杂 UI 都可以逐步补齐。

第二版的核心判断标准是：**系统是否能让 AI 在明确规划、篇幅契约和作者控制下，稳定产出可追踪、可检查、可修改且不像剧情梗概的章节草稿。**
